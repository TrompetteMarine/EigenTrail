# EigenTrail 0.3.0 — UNRELEASED CANDIDATE

Version 0.3.0 coordinates Python, R, Rust and the CLI for the new observed-date
rolling-lineage capability. This document stages a candidate; no tag, GitHub
release, PyPI upload or CRAN submission is authorised by its presence. The latest
published GitHub release is v0.2.2; published Python remains 0.2.0.

## Added capability

* Request-bound `eigentrail.rolling-lineage.v1` reports compare covariance,
  precision, correlation and partial-correlation groups at observed dates.
* Rust producers and independent checkers reconstruct spectral/angle bounds,
  eligible-candidate coverage, categorical decisions and founder reach evidence.
* Direct founder agreement and lag-capped graph reach remain separate. Retained
  predecessors and bottleneck witnesses identify one attaining route without
  inventing a line inside an unresolved block.
* CLI analysis/check commands and raw canonical Python/R JSON routes expose the
  checked computation. Python adds `track_rolling`, a declared-axis panel adapter,
  optional Matplotlib plots and a searchable offline HTML export.

Angular agreement includes equality (`U <= tolerance`), exclusion requires
`L > tolerance`, and remaining cases stay open or explicitly unavailable.
The existing continuous-history `lineage-summary.v1` inputs and strict motion
threshold retain their separate semantics. Full-space containment is trivial
geometry and does not identify an internal direction.

Point-input numerical enclosures and conditional population regions are distinct.
A supplied radius has no implied confidence level. Conditional statements require
the declared joint event, radius provider and applicable transfer assumptions.
Four views of one covariance are dependent evidence. Missing dates are explicit;
feature coordinates and units stay fixed. Partial-correlation spectra may be
indefinite and have no generic explained-variance interpretation.

## Reproduce installation after qualification

Verify the receipt's exact digest and tuple, then install local tested bytes:

```sh
python -m pip install --only-binary=:all: "./candidate/eigentrail-0.3.0-cp314-cp314-macosx_14_0_arm64.whl[plot]"
python -m pip install "./candidate/eigentrail-0.3.0.tar.gz[plot]"
R CMD INSTALL ./candidate/eigentrail_0.3.0.tar.gz
```

Use separate clean environments for the wheel and source checks. The final
candidate receipt will bind both repository commits, the public source tree,
CLI/wheel/R digests, toolchains, numerical backends and remaining evidence gaps.
Git installation must use that receipt's full public commit SHA; no prospective
v0.3.0 tag is an installation target yet.
